# Hardening and re-audit roadmap

Prefer repairing the existing owners over adding skills. No missing capability
in the inspected routes justifies a new directory in this cycle. This is a
bounded conclusion, not proof that the catalogue covers every possible task.

Proposed accountable role: engine maintainer, with domain reviewers for their
respective acceptance decisions. Role acceptance is not recorded. Review on
2026-09-13, sooner if a route, schema, dependency or supported host changes.

| Priority / phase | Existing target | Change and required acceptance |
|---|---|---|
| P0 / finish current experiment | Control-plane validator, contract gate, metadata and existing evidence tables | Integrate specialist corrections; rerun native guards, all tests, changed-skill validation and diff checks. Preserve missing-evidence warnings. Reject empty, missing, malformed and escaping fixtures. |
| P0 / source confidence | `docs/source-registers/skills-engine-currentness-2026-09.json` and Digital Research verifier | Require actual claims, support reviews and valid review windows; prove unsupported and expired fixtures fail. Coordinate during the research engine cycle; a reachable URL alone cannot verify a claim. |
| P1 / failure-path examples | `pwa-offline-first` references; shared API exemplar | Retain atomic business-write/outbox behaviour, stable replay identity, server deduplication and interrupted replay tests. Status text alone is insufficient. |
| P1 / routing handoffs | `android-development`, SDLC and document/product-business owners | Remove absent direct routes and scope project-specific instructions; verify the receiving engine accepts a concrete handoff. Preserve domain ownership. |
| P1 / current guidance | Pipeline, security and maintenance references | Integrate edition-qualified, source-supported wording; test metric classification with worked events and distinguish source scope from implementation conformance. |
| P1 / output evidence | Existing SaaS, AI, database, release and document routes | Retain one connected slice with normal, denied, interrupted and recovery outcomes. Render or execute the actual target output. Use isolated fixtures, not live production. |
| P2 / platform depth | Existing Android, iOS, desktop, GIS and game groups | Add retained target-device/build/player or spatial-oracle evidence where relevant. Unavailable platforms stay NOT ASSESSED. |
| P2 / portability | Existing authoring validators and intended-host adapters | Keep local metadata rules explicit; validate destination-format fixtures and actual host loading before claiming interchange compatibility. |

Phase targets: trustworthy gates first, evidence-backed examples next, then
the policy objective of 95/100 readiness. Intermediate numerical scores are
not forecast without acceptance evidence. Re-assess the same rubric after
each phase and publish no higher than its reporting cap unless its exception
requirements are met. Passing more structural checks alone is not a reason
to increase product-readiness scores.

Reading priorities are the primary sources in the [benchmark register](06-standards-benchmark.md),
selected by the claim being repaired. Public abstracts cannot substantiate
unread normative clauses. Obtain authorised access and review before asserting
such compliance; otherwise keep the limitation explicit. No reading quota or
new book purchase is needed to perform the local regression repairs.

Stop and revise an experiment if it accepts unsupported evidence, discards an
existing runtime declaration or silently selects a different checkout.
Recovery is reversal of only the reviewed experiment patch, followed by the
same negative tests; preserve unrelated user work and the observed failure
record. No commits or pushes are part of this roadmap's present authority.
