## Implementation rules now taught

- Use upload/import, visible filters, active chips, search, and progressive disclosure when the task
  evidence supports them; preserve correction, scope, and recovery.
- Build dashboards around signal, explanation, action/detail, data definition, and data state.
- Choose modal/panel/page based on depth and navigation needs; implement focus entry, containment,
  Escape, accessible name, and focus return for dialogs.
- Model truthful asynchronous states, including queued, active, partial, success, failure, retry,
  cancellation, timeout, and duplicate submission where applicable.
- Honour reduced-motion preferences and verify the target browser matrix rather than claiming a
  generic compatibility pass.
- Keep one product-specific signature choice and refine it with real content; do not copy another
  product's gradients, layout, icons, or copy.
